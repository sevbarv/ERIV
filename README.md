# ERIV · Решения по удержанию

Сайт сравнивает меры удержания конкретного сотрудника за заданный горизонт относительно обычной практики (BAU). Вкладка «Методика» объясняет связь между реестром, оценкой риска и экономикой. Вкладка «Расчёт» включает профиль и историю, замеры контекста, экономику ухода, каталог мер и сравнение.

## Открыть сайт

Распакуйте архив и выполните команду из каталога с этим файлом.

```sh
python -m http.server 8000 --bind 127.0.0.1 --directory site
```

Откройте [http://127.0.0.1:8000/](http://127.0.0.1:8000/). Для этой версии достаточно Python с модулем `http.server`. Формулы, ручное сравнение, импорт результата CATE и экспорт Excel работают в браузере. На Windows при необходимости используйте `py` вместо `python`.

## Опубликовать на GitHub Pages

1. Загрузите содержимое распакованной папки в репозиторий с веткой `main`, включая `.github/workflows/pages.yml`.
2. В настройках репозитория выберите Pages → Build and deployment → GitHub Actions.
3. Запустите `Publish ERIV to GitHub Pages` или отправьте изменение в `main`. Workflow публикует только каталог `site`.

При раздельном размещении задайте адрес сервиса в `site/config.js`. Сайт и API должны открываться по HTTPS. Добавьте origin сайта в `ERIV_ALLOWED_ORIGINS`, например `https://OWNER.github.io` для Pages по адресу `https://OWNER.github.io/REPO/`.

## После публикации на GitHub Pages

GitHub Pages размещает сайт. Для запуска Python и работы с общей базой разверните API из этой же папки. Ниже пример для Render.

1. В Render выберите **New → Web Service**, подключите репозиторий и ветку `main`. Оставьте **Root Directory** пустым, если `site` и `server` лежат в корне.
2. Укажите **Language** = Python 3, **Build Command** = `pip install -r server/requirements.txt` и **Start Command** = `uvicorn server.app:app --host 0.0.0.0 --port $PORT`. Установите `PYTHON_VERSION` = `3.12.12`.
3. В **Environment** задайте `ERIV_ALLOWED_ORIGINS`. Для сайта `https://OWNER.github.io/REPO/` это `https://OWNER.github.io`. Если используете собственный домен, укажите его origin. При необходимости разделите несколько адресов запятой.
4. После развёртывания откройте адрес Render с `/api/health`. Ответ должен быть `{"service":"ERIV"}`.
5. В `site/config.js` укажите `window.ERIV_API_URL = "https://ВАШ-СЕРВИС.onrender.com";`. Сохраните файл в `main` и дождитесь завершения GitHub Actions. Теперь кнопка «Запустить Python» отправляет расчёт на сервер. Вход в базу для расчёта не требуется.

[Развёртывание FastAPI на Render](https://render.com/docs/deploy-fastapi) · [Среда Render](https://render.com/docs/configure-environment-variables)

## Подключить Google Таблицу «Сотрудники»

1. В Google Cloud выберите свой проект и включите **Google Sheets API**. В **Google Auth Platform** заполните **Branding** и настройте **Audience**. Для внешнего приложения в режиме тестирования добавьте в список тестовых пользователей аккаунты, которым нужен доступ. Для внутреннего приложения Google Workspace используйте аккаунты своей организации.
2. В **Clients** создайте **OAuth client ID** типа **Web application**. Добавьте адрес GitHub Pages в **Authorized JavaScript origins**. Например, для `https://OWNER.github.io/REPO/` добавьте `https://OWNER.github.io`. Если открываете сайт напрямую на Render, добавьте и этот origin. Скопируйте Client ID. В приложении используется JavaScript-обработчик входа, поэтому Redirect URI и Client Secret для него не нужны.
3. В Render добавьте `ERIV_GOOGLE_CLIENT_ID` со скопированным Client ID, `ERIV_GOOGLE_ALLOWED_EMAILS` с разрешёнными адресами Gmail или Google Workspace через запятую и `ERIV_SHEET_ID` с идентификатором таблицы между `/d/` и `/edit`. Эти значения задаются на сервере.
4. Для синхронизации создайте сервисный аккаунт в Google Cloud и предоставьте его адресу право **Редактор** на таблицу. Оставьте общий доступ к таблице ограниченным. Для прямого редактирования в Google Таблицах используйте свой Google-аккаунт с правами редактора.
5. На Render загрузите JSON-ключ сервисного аккаунта в **Environment → Secret Files**, например под именем `eriv-sheets.json`. Задайте `GOOGLE_APPLICATION_CREDENTIALS=/etc/secrets/eriv-sheets.json`. При размещении в Google Cloud можно использовать привязанный сервисный аккаунт и `ERIV_USE_GOOGLE_ADC=1`. Храните JSON-ключ только в секретах хостинга. Сохраните настройки и дождитесь развёртывания.
6. На сайте нажмите «Доступ к базе», выберите разрешённый Google-аккаунт и откройте вкладку «База». Кнопка «Открыть Google Таблицу» ведёт к исходному реестру. После подтверждения обезличивания кнопка «В Google Таблицы» переносит выбранную локальную запись на лист «Сотрудники». Строка 5 содержит его технические ключи. Строки реестра начинаются с 6-й.

Если обновляете прежнюю установку, удалите из среды хостинга переменные `ERIV_ADMIN_USER` и `ERIV_ADMIN_VERIFIER`. Калькулятор сохраняет введённые записи в браузере. Общий реестр открывается через подтверждённый Google-аккаунт. Чтобы использовать историю из общей таблицы в расчёте, скачайте лист «Сотрудники» как CSV и загрузите его в разделе «Контекст».

[Настройка входа Google](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid) · [Доступ сервисного аккаунта к Google Таблице](https://developers.google.com/workspace/guides/create-credentials)

## Локальный запуск Python-сервера

Используйте Python 3.11 или 3.12. Создайте виртуальное окружение через `python -m venv .venv` и активируйте его. Из корня проекта выполните:

```sh
python -m pip install -r server/requirements.txt
python -m uvicorn server.app:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000/`. Для локального запуска оставьте адрес API в `site/config.js` пустым. Если хотите проверить Google-базу локально, настройте переменные по образцу `.env.example` и запустите Uvicorn с `--env-file .env`. Добавьте `http://127.0.0.1:8000` в разрешённые JavaScript origins OAuth-клиента и откройте сайт с этого же адреса.

## Расчёт

- Для сценария без истории задайте общий риск P₀ и основание ручной оценки. У каждой доступной меры заполните вероятность, цену и доли затрат, проверьте полноту статей.
- В «Экономике» выберите план ухода и базу HRTech. Нулём отмечайте подтверждённое отсутствие расхода. Цена ухода может иметь отрицательный знак, если выбранный план даёт экономию.
- Для оценки по истории сохраните назначения и исходы за единый горизонт. В разделе «Контекст» можно загрузить CSV листа «Сотрудники» с техническими ключами из строки 5. В расчёт входят строки «История» из CSV и записи этого браузера. Общая Google Таблица открывается во вкладке «База» после входа через Google. В «Контексте» задайте срез, роли X/W и дизайн. «Запустить Python» отправляет собранную книгу на сервер без входа. Для портфеля задайте бюджет и лимитируемые затраты в карточках доступных мер. При нескольких профилях экономика, введённая в интерфейсе, относится к открытому профилю. Для портфеля нескольких случаев используйте объединённый CSV экономики в командной строке.
- В «Результате» можно переключить сценарий, раскрыть расчёт мер, изучить поток, порог безубыточности и выгрузить книгу с формулами, реестром и используемым импортом. Индивидуальные допущения и контекст текущей сессии можно сохранить в этой книге.

Вместо вызова API можно запустить исходную методику локально, используя скачанный из сайта Excel. Загрузите полученный `retention_decisions.csv` кнопкой «Импорт CATE». Связь идёт по компании, анализу, коду сотрудника, дате и горизонту. Если для меры нужно загрузить вероятность из Python, укажите источник «Импорт» в её карточке.

```sh
python server/eriv_retention.py --workbook ERIV-calculation.xlsx --out results
python server/eriv_retention.py --workbook ERIV-calculation.xlsx --economics economics.csv --budget 250000 --out results
```

Python использует только логистическую модель BAU, DoWhy и LinearDML. Интервалы относятся к условному среднему эффекту. Для переноса политики на будущие когорты предусмотрите проверку на отложенных данных или в пилоте. OLS описывает связи между контекстными индексами. NSM в наблюдательном сравнении показывает разность долей.

## Интерфейс и источники

На мобильном сохранён порядок разделов. Форма показывает применимый блок расходов, метки остаются над полями, а таблица результатов становится списком карточек. Montserrat для латиницы и кириллицы включён в комплект. Палитра исходной книги используется для заголовков таблиц, ввода и расчётных значений. Для белых меток ввода выбран более тёмный зелёный с читаемым контрастом.

- Для навигации и расположения действий разобраны веб-интерфейс и мобильный сценарий Linear. Для форм использованы выводы Baymard о постоянных подписях полей. [Linear](https://linear.app/now/behind-the-latest-design-refresh) · [Linear Mobile](https://linear.app/mobile) · [Baymard](https://baymard.com/research-articles/mobile-form-usability-label-position)
- По материалу Википедии проверены конкретность формулировок, повторения и рекламные эпитеты. Исследования генеративных интерфейсов разбирают непоследовательность компонентов и разрыв между описанной логикой и поведением. В ERIV проверялись повторяющиеся элементы, переходы, сохранение, выбор меры и скачивание Excel. [Википедия](https://ru.wikipedia.org/wiki/Википедия:Признаки_сгенерированности_текста) · [Обзор Irmak и Mahmoud](https://doi.org/10.3390/computers15040238) · [Design Theater](https://arxiv.org/abs/2607.22928)
- GitHub Pages размещает статическую часть. В отдельном API выполняются расчёт Python, проверка входа Google и запись в закрытую таблицу. [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) · [Google Workspace](https://developers.google.com/workspace/guides/create-credentials)
